# Лабораторная работа №1: реализация алгоритмов сортировки на ЯП С

Шаблон проекта для выполнения лабораторной работы по алгоритмам сортировки.
В репозитории находятся файлы `main.c`, `sortings.h` и файлы проекта Visual Studio 2026.
* Файл `main.c` содержит точку входа в программу.
* Файл `sortings.h` содержит прототипы функций сортировки и дополнительных функций для ввода/вывода, генерации данных и т.д.

## Порядок выполнения работы

### 1. Создание форка (выполняет лид команды)

Один человек в команде — **лид** — создаёт форк этого репозитория:

1. Откройте страницу этого репозитория на GitHub.
2. Нажмите кнопку **Fork** в правом верхнем углу.
3. На странице создания форка нажмите **Create fork**.

**Название форка должно содержать фамилии всех участников команды**,
например: `sorting-lab-ivanov-petrov-sidorov`. Переименовать репозиторий
можно в **Settings → Repository name**.

### 2. Клонирование форка (выполняют остальные участники)

Остальные участники команды клонируют **форк команды** (не исходный
репозиторий преподавателя) - для этого воспользуйтесь следующими командами:

#### 2.1: Перейдите в каталог, где вы хотите сохранить проект
```
cd путь/к/вашей/папке
```

#### 2.2: Клонируйте форк команды (замените URL на URL вашего форка)
```
git clone https://github.com/ваш-аккаунт/sorting-lab-ivanov-petrov-sidorov.git
```

#### 2.3: Перейдите в клонированный каталог
```
cd sorting-lab-ivanov-petrov-sidorov
```

> **Важно:** клонировать нужно именно форк команды. Работа в исходном
> репозитории преподавателя не допускается.

### 3. Распределение обязанностей

Внутри команды роли распределяются самостоятельно. Рекомендуемое разделение:

1. Лид: осуществляет общее руководство, работает с дополнительными функциями ИЛИ с предложенными функциями сортировок.
2. Первый участник: работает с дополнительными функциями ИЛИ с предложенными функциями сортировок (по договорённости с лидом).
3. Второй участник: работает с функцией сортировки, предложенной для самостоятельного изучения.

Распределение можно менять по договорённости, главное — чтобы каждый
участник внёс свой вклад и мог объяснить свой код.

### 4. Работа с репозиторием

Каждый участник работает **в своей локальной копии** репозитория.
Все команды выполняются в терминале из папки проекта.

#### 4.1: Перед началом работы получите изменения, отправленные другими участниками
```
git pull
```
Это подтянет в вашу локальную копию всё, что уже успели отправить
в форк команды другие участники.

#### 4.2: Внесите изменения в код
Отредактируйте файлы `main.c` и `sortings.h` в вашем редакторе или
в Visual Studio 2026.

#### 4.3: Посмотрите, какие файлы изменены
```
git status
```
Изменённые файлы будут перечислены в разделе `Changes not staged for commit`.

#### 4.4: Добавьте изменённые файлы в индекс
```
git add .
```
Точка означает «добавить все изменения в текущей папке».
Если нужно добавить только конкретный файл, укажите его: `git add main.c`.

#### 4.5: Зафиксируйте изменения (commit)
```
git commit -m "краткое описание того, что сделано"
```
В кавычках — осмысленное сообщение, например `"реализована сортировка Шелла"`
или `"добавлена функция saveResults"`.

#### 4.6: Отправьте изменения в форк команды (push)
```
git push
```
Изменения уйдут в ваш форк на GitHub. Если это первая отправка
в новую ветку, Git может предложить команду вида
`git push --set-upstream origin имя-ветки` — выполните её.

#### 4.7: Контроль со стороны лида
Лид следит, чтобы все участники отправили свои изменения
(`git status` показывает `Your branch is up to date`),
и чтобы проект собирался без ошибок.

### 5. Сдача работы

Сдача проходит **очно, в присутствии преподавателя**:

1. Команда при преподавателе клонирует репозиторий форка.
2. Проект собирается и запускается.
3. Каждый участник рассказывает, что он делал, как это реализовано,
   и объясняет свой код.

## Варианты алгоритмов для самостоятельного изучения

Помимо алгоритмов, предложенных в шаблоне, каждый участник (или команда)
реализует **один вариант** из списка ниже. Конкретный вариант для каждой команды выдаётся на паре.

- Сортировка вставками (insertion sort)
- Сортировка выбором (selection sort)
- Сортировка Шелла (Shell sort)
- Пирамидальная сортировка (heap sort)
- Сортировка Бэтчера (bitonic sort — упрощённый вариант)

> Варианты раздаются преподавателем на паре лично. Не выбирайте вариант
> самостоятельно, не согласовав его с преподавателем.

## Требования к сдаче

- Проект должен собираться в Visual Studio 2026 без ошибок.
- Все изменения должны быть отправлены (push) в форк команды.
- Название форка содержит фамилии участников.
- Каждый участник понимает и может объяснить написанный им код.
